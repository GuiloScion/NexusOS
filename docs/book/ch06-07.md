# Chapter 6. Interrupts: the IDT, exceptions, the PIC, the timer, and the keyboard

So far the kernel runs straight through. But a real OS must **react** to things: a key is pressed, a timer fires, the CPU hits an error. The mechanism for all of this is the **interrupt**. The CPU stops what it is doing, jumps to a handler you registered, then resumes. This chapter wires that up.

## Two kinds of interrupts

- **Exceptions** are raised by the CPU itself, on errors: divide-by-zero, page fault (bad memory access), general protection fault, invalid opcode. Vectors 0–31 are reserved for these by the architecture.
- **Hardware interrupts** ("IRQs") are raised by devices: the timer (IRQ0), the keyboard (IRQ1), the disk (IRQ14), the mouse (IRQ12). They are delivered through a chip called the **PIC** (the 8259A, on legacy hardware).

Both kinds are dispatched through the same table: the **IDT**.

## The IDT (Interrupt Descriptor Table)

The IDT is an array of 256 entries. Entry N says "when interrupt N fires, jump here." You fill it in, then load it with the `lidt` instruction. NexusOS builds all 256 entries in `kernel/idt.c`, and each entry has a fixed 16-byte layout that packs the handler's 64-bit address across three non-contiguous fields, a target code-segment selector, and a type/permission byte.

*Listing 6.1. `kernel/idt.c`, lines 23–56: the IDT gate structure and the helper that fills one in.*

```c
typedef struct PACKED {
    uint16_t offset_low;
    uint16_t selector;
    uint8_t  ist;
    uint8_t  type_attr;
    uint16_t offset_mid;
    uint32_t offset_high;
    uint32_t reserved;
} idt_gate_t;

typedef struct PACKED {
    uint16_t limit;
    uint64_t base;
} idt_pointer_t;

#define IDT_SIZE        256
#define KERNEL_CS       0x18    /* 64-bit code seg (matches kernel_entry.asm) */
#define GATE_INTERRUPT  0x8E    /* present, DPL=0, type=interrupt gate */

static idt_gate_t  idt[IDT_SIZE] ALIGN(16);

static void idt_set_gate(uint8_t vector, uintptr_t handler) {
    idt[vector].offset_low  = (uint16_t)(handler & 0xFFFF);
    idt[vector].selector    = KERNEL_CS;
    idt[vector].ist         = 0;
    idt[vector].type_attr   = GATE_INTERRUPT;
    idt[vector].offset_mid  = (uint16_t)((handler >> 16) & 0xFFFF);
    idt[vector].offset_high = (uint32_t)((handler >> 32) & 0xFFFFFFFF);
    idt[vector].reserved    = 0;
}
```

`PACKED` and `ALIGN(16)` are macros that wrap `__attribute__((packed))` and `__attribute__((aligned(16)))`. The "packed" attribute is critical: without it, the compiler is free to insert padding between fields and the CPU will read a malformed descriptor. The 16-byte alignment of the array isn't strictly required but is cheap insurance for cache behaviour.

Each entry points at a small assembly **stub**. Why assembly? Because on entry to a handler you must save the CPU registers before running any C code (C would clobber them on the first instruction), and some interrupts push an error code on the stack while others do not. The stubs normalise all that, then call a single C dispatcher. NexusOS generates 256 stubs in `kernel/idt_stubs.asm` that all funnel into one common path; the C side just sees an `interrupt_frame_t` pointer.

## The dispatcher

The common stub calls one C function for every interrupt. It looks at the vector and routes accordingly.

*Listing 6.2. `kernel/idt.c`, lines 108–122: the unified interrupt dispatcher.*

```c
void interrupt_dispatch(interrupt_frame_t *frame) {
    uint64_t v = frame->vector;

    if (v < 32) {
        panic_on_exception(frame);
    } else if (v < 32 + 16) {
        uint8_t irq = (uint8_t)(v - 32);
        if (irq_handlers[irq]) irq_handlers[irq](frame);
    } else if (v == 0x80) {
        /* Software yield: invoked by tasks via `int $0x80`. */
        extern void scheduler_tick(interrupt_frame_t *);
        scheduler_tick(frame);
    }
    /* Other vectors are not generated yet; ignore. */
}
```

This is the pivot point of the kernel's event loop. Three vector ranges matter: 0–31 are exceptions (anything here is a kernel bug, so we panic); 32–47 are the 16 IRQs (we look up the device handler); `0x80` is our software interrupt for the yield operation that the scheduler will use in Chapter 8.

## Handling exceptions: your first debugger

When your kernel has a bug, like dereferencing a bad pointer or dividing by zero, the CPU raises an exception. If you have no handler, it escalates to a *double fault*; if that has no handler, a **triple fault** reboots the machine. That is what you have been seeing in QEMU when something goes wrong.

With an IDT in place, you can instead **catch** the exception and print diagnostics. NexusOS's exception handler dumps the vector name, the instruction pointer, the faulting address (`CR2`, for page faults), and every register, then halts:

*Listing 6.3. `kernel/idt.c`, lines 83–101: the panic dump on any unhandled exception.*

```c
static NORETURN void panic_on_exception(interrupt_frame_t *f) {
    console_puts("\n\n=== CPU EXCEPTION ===\n");
    console_puts(exception_name(f->vector));
    console_puts("\n  vector = "); console_put_dec(f->vector);
    console_puts("\n  error  = "); console_put_hex(f->error_code);
    console_puts("\n  rip    = "); console_put_hex(f->rip);
    console_puts("\n  cs     = "); console_put_hex(f->cs);
    console_puts("\n  rflags = "); console_put_hex(f->rflags);
    console_puts("\n  rsp    = "); console_put_hex(f->rsp);
    if (f->vector == 14) {
        console_puts("\n  cr2    = "); console_put_hex(read_cr2());
    }
    console_puts("\n  rax    = "); console_put_hex(f->rax);
    console_puts("\n  rbx    = "); console_put_hex(f->rbx);
    console_puts("\n  rcx    = "); console_put_hex(f->rcx);
    console_puts("\n  rdx    = "); console_put_hex(f->rdx);
    console_puts("\n=== HALTED ===\n");
    for (;;) { cli(); hlt(); }
}
```

That panic dump turns "the machine mysteriously rebooted" into "I dereferenced null at `RIP=0x10488`." It is worth building early; you will pay yourself back the same afternoon.

## The PIC: routing device interrupts

The legacy **8259A PIC** (a pair of chips: master at I/O ports `0x20`/`0x21` and slave at `0xA0`/`0xA1`) routes the 16 hardware IRQ lines to CPU interrupt vectors. Two things you must do:

1. **Remap it.** By default the PIC delivers IRQs on vectors 0–15, which *collide* with the CPU's exception vectors. Remap the IRQs to vectors `0x20–0x2F` so they don't clash.
2. **Acknowledge (EOI).** After handling an IRQ, send an "end of interrupt" byte so the PIC will deliver the next one. Forget this and interrupts stop after the first.

You can also **mask** individual IRQs to disable them until a driver is ready. The remap is a fixed four-byte "ICW" sequence:

*Listing 6.4. `kernel/pic.c`, lines 23–52: the PIC remap and default-masked init.*

```c
void pic_init(void) {
    /* Save current masks. */
    uint8_t mask_m = inb(PIC_M_DATA);
    uint8_t mask_s = inb(PIC_S_DATA);

    /* ICW1: start init in cascade mode, expect ICW4. */
    outb(PIC_M_CMD, ICW1_INIT); io_wait();
    outb(PIC_S_CMD, ICW1_INIT); io_wait();

    /* ICW2: vector offset (master 0x20..0x27, slave 0x28..0x2F). */
    outb(PIC_M_DATA, IRQ_BASE);     io_wait();
    outb(PIC_S_DATA, IRQ_BASE + 8); io_wait();

    /* ICW3: tell master that slave is on IRQ2; tell slave its identity. */
    outb(PIC_M_DATA, 0x04); io_wait();
    outb(PIC_S_DATA, 0x02); io_wait();

    /* ICW4: 8086 mode. */
    outb(PIC_M_DATA, ICW4_8086); io_wait();
    outb(PIC_S_DATA, ICW4_8086); io_wait();

    /* Restore masks then default to all masked. */
    outb(PIC_M_DATA, mask_m);
    outb(PIC_S_DATA, mask_s);
    outb(PIC_M_DATA, 0xFF);
    outb(PIC_S_DATA, 0xFF);
}
```

Two implementation tricks here: the `io_wait()` between writes is a stall to give the slow PIC chip time to latch each command before the next one (writing to unused port `0x80` is the traditional way), and the final `0xFF` masks force all IRQs off so nothing fires until a driver explicitly unmasks its line.

## The timer (PIT): your heartbeat

The **Programmable Interval Timer** (8253/8254) can be set to fire IRQ0 at a fixed rate. NexusOS programs it for 100 Hz; each tick increments a counter and, later, drives the scheduler's preemption. A steady timer interrupt is the heartbeat of a multitasking OS: it is what lets the kernel take the CPU back from a running task.

*Listing 6.5. `kernel/pit.c`, lines 9–33: programming a 100 Hz tick.*

```c
#define PIT_CH0     0x40
#define PIT_CMD     0x43
#define PIT_FREQ    1193182u    /* base oscillator frequency, Hz */

static volatile uint64_t ticks;

static void pit_irq(interrupt_frame_t *frame) {
    pic_send_eoi(0);             /* EOI before any path that may not return */
    ticks++;
    scheduler_tick(frame);       /* may not return (tail-calls _switch_to) */
}

void pit_init(uint32_t hz) {
    uint32_t divisor = PIT_FREQ / hz;
    if (divisor == 0) divisor = 1;
    if (divisor > 0xFFFF) divisor = 0xFFFF;

    /* Channel 0, lobyte/hibyte, mode 3 (square wave), binary. */
    outb(PIT_CMD, 0x36);
    outb(PIT_CH0, (uint8_t)(divisor & 0xFF));
    outb(PIT_CH0, (uint8_t)((divisor >> 8) & 0xFF));

    irq_register(0, pit_irq);
    pic_unmask(0);
}
```

The order of operations in `pit_irq` matters and is worth absorbing: we send the EOI **first**, before calling `scheduler_tick`, because the scheduler may switch tasks and *never return from this function*. The new task `iretq`s away from a completely different stack. If the EOI came last, a context switch on this tick would cause the PIC to silently drop every subsequent IRQ0.

## The keyboard

The PS/2 keyboard raises IRQ1 each time a key is pressed or released. The handler reads a **scancode** from port `0x60`, translates it to a character (via a lookup table for the US layout), tracks modifiers (Shift, Caps Lock), and pushes the result into a ring buffer that the shell reads.

*Listing 6.6. `kernel/keyboard.c`, lines 54–84: the IRQ1 handler.*

```c
static void keyboard_irq(interrupt_frame_t *frame) {
    (void)frame;
    pic_send_eoi(1);              /* EOI first; symmetric with pit_irq */
    uint8_t sc = inb(KBD_DATA);

    if (sc == 0xE0) { ext_prefix = true; return; }
    if (ext_prefix) { ext_prefix = false; return; }

    bool released = (sc & 0x80) != 0;
    uint8_t code  = sc & 0x7F;

    /* Modifier handling. */
    if (code == 0x2A || code == 0x36) {     /* L-Shift / R-Shift */
        shift_down = !released;
        return;
    }
    if (!released && code == 0x3A) {        /* Caps Lock make */
        caps_lock = !caps_lock;
        return;
    }
    if (released) return;

    if (code >= 128) return;
    char c = shift_down ? map_shifted[code] : map_unshifted[code];

    /* Caps Lock only affects letters. */
    if (caps_lock && c >= 'a' && c <= 'z') c = (char)(c - 32);
    else if (caps_lock && shift_down && c >= 'A' && c <= 'Z') c = (char)(c + 32);

    if (c) ring_push(c);
}
```

Two subtleties: the *extended* scancode prefix `0xE0` (used by arrow keys and the right-hand modifier keys) is detected and the following byte discarded. We only care about the basic layout. And the handler **must be short**. It reads the byte, updates state, drops a character in the ring buffer, and returns. Anything heavier (echoing to the screen, parsing a command) waits for the foreground task to dequeue.

## The flow, end to end

```text
key pressed
  -> PIC raises IRQ1 -> CPU jumps to IDT entry 0x21
  -> assembly stub saves registers, calls interrupt_dispatch
  -> dispatch finds the IRQ1 handler (kbd_irq), calls it
  -> handler reads scancode (port 0x60), pushes char, sends EOI
  -> stub restores registers, iretq
  -> later, the shell reads the char from the ring buffer
```

Once interrupts work, your kernel is *alive*. It ticks, it responds to keys, it catches its own mistakes and tells you about them. The catch: interrupts can fire at any moment, even in the middle of your code. That introduces **concurrency**, which we will tame with a scheduler and locks (Chapter 8). But first, the thing every subsystem depends on: memory.

## Exercises

1. **Deliberately page-fault.** From `kernel_main`, after `idt_init` and `pic_init`, write `*((volatile uint64_t*)0xDEADBEEF000) = 1;`. You should see a `#PF Page Fault` panic with `RIP=0x...` pointing at the writing instruction and `CR2=0xDEADBEEF000`. Verify the `RIP` matches the address of that line by disassembling your kernel with `objdump -d build/kernel.elf | less` and searching for the value.

   *Hint:* If you see a reboot instead of a panic, the IDT is not actually loaded. Go look at where you call `idt_init` and confirm it runs before the bad write. The fault is benign; once you halt in the panic, QEMU shows the same dump on serial.

2. **Count timer ticks.** After `pit_init(100)`, spin in a loop reading `pit_ticks()` (the global counter incremented by the IRQ0 handler) and print it once per second (1 second = 100 ticks). If your loop is `while (pit_ticks() < deadline) hlt();`, the `hlt` ensures the CPU sleeps between ticks instead of burning the core. This pattern, `hlt` until the next interrupt, is the basis of an idle task.

   *Hint:* The first time you write this loop without `hlt`, the kernel will pin a core at 100% in QEMU. Watch your host's CPU usage; the difference between busy-loop and `hlt`-loop is enormous.

3. **Read a few keystrokes.** Press keys after `keyboard_init`; the IRQ1 handler should drop characters into the ring buffer. Write `keyboard_getc` to spin until a character is available, then echo it. If you press `a`, you should see `a`. If you press `Shift+a`, you should see `A`. Now you have an interactive kernel: *the keyboard talks to your code*.

   *Hint:* For the spin-until-available loop, the trick is `__asm__ volatile("sti; hlt");`, which re-enables interrupts and sleeps. Without `sti`, the kernel may be in a critical section with IRQs disabled and the keyboard interrupt will never fire.

4. **Pinpoint a hang with stage markers.** Add `console_putc('1')` after `console_init`, `'2'` after `idt_init`, `'3'` after `pic_init`, `'4'` after `pit_init`, `'5'` after `keyboard_init`. Then break each subsystem in turn (for instance, comment out `outb(PIC_M_CMD, ICW1_INIT)` so the remap never happens). The last character on screen tells you exactly where the kernel died. This single technique will save you many hours in Chapter 12.

   *Hint:* On real hardware where the screen may be black, the same markers go to serial. NexusOS used this exact trick to localise a real-hardware VBE hang to "inside the BIOS int 10h", a debug result you could not get any other way.

# Chapter 7. Memory management: physical frames, paging, and the heap

Almost everything the kernel does eventually needs memory: page tables, task stacks, buffers, a heap. Managing memory is three layered problems, each built on the one below:

1. **Physical memory.** Which 4 KiB chunks of real RAM are free? (The PMM.)
2. **Virtual memory.** Map virtual addresses to physical ones via page tables. (The VMM.)
3. **The heap.** `kmalloc` and `kfree` for arbitrary-sized allocations.

## Layer 1: the physical memory manager (PMM)

First: *how much RAM is there, and where?* You cannot probe this safely by poking addresses; a stray write to MMIO could brick a device. Instead the BIOS told you, via the **E820 map** the bootloader saved in real mode. Each entry is `(base, length, type)`; `type == 1` means usable RAM, everything else is reserved (firmware, MMIO, ACPI).

A simple and robust PMM is a **bitmap allocator**: one bit per 4 KiB physical *frame*, `1` = used, `0` = free. NexusOS does exactly this. The init routine is short enough to read end-to-end and is worth doing so. It is the canonical "use the firmware's memory map" pattern:

*Listing 7.1. `kernel/pmm.c`, lines 51–114: the PMM init walks E820, sizes the bitmap, reserves the kernel, then frees the usable regions.*

```c
void pmm_init(uintptr_t kernel_end_phys) {
    uint32_t        count   = *(volatile uint32_t *)E820_COUNT_ADDR;
    e820_entry_t   *entries = (e820_entry_t *)E820_ENTRIES_ADDR;

    /* Find highest physical address claimed by USABLE E820 entries.
     * Including reserved/MMIO regions (PCI hole at ~1 TiB on QEMU) would
     * balloon the bitmap into tens of MiB and overrun the early 2 MiB
     * identity map, clobbering the page tables at 0x70000. */
    uint64_t max_addr     = 0;
    bool     have_usable  = false;
    for (uint32_t i = 0; i < count; i++) {
        if (entries[i].type != 1) continue;
        have_usable = true;
        uint64_t top = entries[i].base + entries[i].length;
        if (top > max_addr) max_addr = top;
    }

    /* Some real firmware (seen on an ASUS board under CSM) returns an E820
     * map containing only reserved/MMIO regions and no usable RAM at all.
     * The machine clearly has memory, so fall back to a conservative 128 MiB
     * usable region above 1 MiB rather than failing to boot. */
    if (!have_usable) {
        console_puts("[pmm] no usable E820 region; assuming 128 MiB\n");
        max_addr = PMM_SYNTH_BASE + PMM_SYNTH_LEN;
    }

    bitmap_bits  = (max_addr + PAGE_SIZE - 1) / PAGE_SIZE;
    bitmap_bytes = (bitmap_bits + 7) / 8;

    /* Place bitmap after kernel, page-aligned. */
    uintptr_t bitmap_pa = (kernel_end_phys + PAGE_SIZE - 1)
                          & ~(uintptr_t)(PAGE_SIZE - 1);
    bitmap = (uint8_t *)bitmap_pa;

    /* Start with everything marked used. */
    memset(bitmap, 0xFF, bitmap_bytes);
    used_count = bitmap_bits;

    /* Free what E820 says is usable (or the assumed region if there was none). */
    if (have_usable) {
        for (uint32_t i = 0; i < count; i++) {
            if (entries[i].type == 1) {
                mark_free_range((uintptr_t)entries[i].base, entries[i].length);
            }
        }
    } else {
        mark_free_range(PMM_SYNTH_BASE, PMM_SYNTH_LEN);
    }

    /* Reserve low memory, kernel image, and the bitmap itself. */
    mark_used_range(0, LOW_MEM_RESERVED);
    mark_used_range(LOW_MEM_RESERVED,
                    (kernel_end_phys > LOW_MEM_RESERVED)
                        ? (kernel_end_phys - LOW_MEM_RESERVED) : 0);
    mark_used_range(bitmap_pa, bitmap_bytes);
}
```

Notice the *defensive fallback* in the middle: some real firmware returns an E820 map with **no usable region at all** (this happened to NexusOS on an ASUS board). Rather than fail, the PMM assumes a conservative 128 MiB above 1 MiB. Defensive fallbacks like this are what make an OS survive the messiness of real machines, and Chapter 12 has the full story of how this one was earned.

Allocation is a linear scan with a "next free" hint:

*Listing 7.2. `kernel/pmm.c`, lines 116–140: the allocator and freer.*

```c
uintptr_t pmm_alloc_frame(void) {
    for (uint64_t pass = 0; pass < 2; pass++) {
        uint64_t start = (pass == 0) ? next_free_hint : 0;
        uint64_t stop  = (pass == 0) ? bitmap_bits   : next_free_hint;
        for (uint64_t i = start; i < stop; i++) {
            if (!bit_test(i)) {
                bit_set(i);
                used_count++;
                next_free_hint = i + 1;
                return (uintptr_t)i * PAGE_SIZE;
            }
        }
    }
    return 0;
}

void pmm_free_frame(uintptr_t pa) {
    uint64_t i = pa / PAGE_SIZE;
    if (i >= bitmap_bits) return;
    if (bit_test(i)) {
        bit_clear(i);
        used_count--;
        if (i < next_free_hint) next_free_hint = i;
    }
}
```

Two passes from the hint means we wrap around to the start of the bitmap if the upper region is full, which keeps allocation O(N) only in the worst case rather than always.

## Layer 2: virtual memory (paging)

Paging maps **virtual addresses** (what code uses) to **physical frames** (real RAM), in 4 KiB pages, through the four-level table tree (PML4 → PDPT → PD → PT) the boot stub set up minimally. Now that you have a PMM, you build *real* page tables. NexusOS's `kernel/vmm.c` first **identity-maps** all of RAM (virtual address == physical address) with 2 MiB pages for simplicity, then installs a fresh kernel PML4 and exposes a 4 KiB `map` API for fine-grained mappings later (the heap and the framebuffer).

*Listing 7.3. `kernel/vmm.c`, lines 98–136: the core 4 KiB `vmm_map` operation walks all four levels, allocating tables on the way.*

```c
bool vmm_map(uintptr_t virt, uintptr_t phys, uint64_t flags) {
    uint64_t i4 = pml4_index(virt);
    uint64_t i3 = pdpt_index(virt);
    uint64_t i2 = pd_index(virt);
    uint64_t i1 = pt_index(virt);

    uint64_t *pdpt;
    if (!(kernel_pml4[i4] & PTE_PRESENT)) {
        pdpt = alloc_table();
        if (!pdpt) return false;
        kernel_pml4[i4] = (uint64_t)(uintptr_t)pdpt | PTE_KERNEL_RW;
    } else {
        pdpt = next_table(kernel_pml4[i4]);
    }

    uint64_t *pd;
    if (!(pdpt[i3] & PTE_PRESENT)) {
        pd = alloc_table();
        if (!pd) return false;
        pdpt[i3] = (uint64_t)(uintptr_t)pd | PTE_KERNEL_RW;
    } else {
        if (pdpt[i3] & PTE_HUGE) return false;   /* 1 GiB leaf -- refuse */
        pd = next_table(pdpt[i3]);
    }

    uint64_t *pt;
    if (!(pd[i2] & PTE_PRESENT)) {
        pt = alloc_table();
        if (!pt) return false;
        pd[i2] = (uint64_t)(uintptr_t)pt | PTE_KERNEL_RW;
    } else {
        if (pd[i2] & PTE_HUGE) return false;     /* 2 MiB leaf -- refuse */
        pt = next_table(pd[i2]);
    }

    pt[i1] = (phys & PAGE_MASK) | (flags & ~PTE_HUGE) | PTE_PRESENT;
    invlpg(virt);
    return true;
}
```

The pattern is straightforward and worth memorising: at each level, if the entry is present, descend into the existing table; otherwise allocate a new table from the PMM, point the parent at it, and descend. At the leaf, write the final entry. The `invlpg` at the end flushes the CPU's TLB for that single virtual address; without it, the CPU may keep using the old (now-stale) translation it cached.

Why identity-map? It is the simplest possible choice: pointers are physical addresses, and there is no translation to reason about. Later, real process isolation will use *separate* address spaces per process, but that is a Chapter 13 concern.

## Layer 3: the kernel heap (`kmalloc`)

Frames are 4 KiB; you often want 37 bytes, or 9000. A **heap** sits on top of the VMM and hands out arbitrary sizes. NexusOS's `kernel/kmalloc.c` is a classic **first-fit free list**: the heap lives at a high virtual address (`0x200000000`), is **demand-grown** (when it needs more space, it asks the PMM for frames and `vmm_map`s them in, so unused heap costs nothing), and each block has a header in a doubly-linked list.

*Listing 7.4. `kernel/kmalloc.c`, lines 31–37 and 94–135: the block layout and the first-fit allocator.*

```c
typedef struct block_header {
    size_t                size;     /* total bytes incl. this header */
    bool                  free;
    uint8_t               _pad[7];
    struct block_header  *prev;
    struct block_header  *next;
} block_header_t;

/* ... */

void *kmalloc(size_t n) {
    if (n == 0) return NULL;
    size_t needed = ALIGN_UP(n + HDR_SIZE, 16);

    for (block_header_t *b = heap_head; b; b = b->next) {
        if (b->free && b->size >= needed) {
            try_split(b, needed);
            b->free = false;
            return (void *)((uint8_t *)b + HDR_SIZE);
        }
    }

    /* No fit -- grow heap and retry once. */
    size_t pages = (needed + 4095) / 4096;
    if (pages < 16) pages = 16;
    uintptr_t old_end = heap_end_virt;
    if (!grow_heap(pages)) return NULL;

    block_header_t *tail = (block_header_t *)old_end;
    tail->size = pages * 4096;
    tail->free = true;
    tail->next = NULL;

    block_header_t *last = heap_head;
    while (last->next) last = last->next;
    tail->prev = last;
    last->next = tail;

    if (last->free) {
        last->size += tail->size;
        last->next  = NULL;
        tail = last;
    }

    if (tail->size < needed) return NULL;
    try_split(tail, needed);
    tail->free = false;
    return (void *)((uint8_t *)tail + HDR_SIZE);
}
```

`kfree` is shorter, but its job is **coalescing**: when a block is freed, merge it with adjacent free neighbours. Without that, the heap fragments over time: many small holes between busy blocks, and large allocations eventually fail even when total free space is huge.

*Listing 7.5. `kernel/kmalloc.c`, lines 137–156: free with forward and backward coalescing.*

```c
void kfree(void *p) {
    if (!p) return;
    block_header_t *b = (block_header_t *)((uint8_t *)p - HDR_SIZE);
    b->free = true;

    /* Coalesce forward. */
    if (b->next && b->next->free) {
        block_header_t *n = b->next;
        b->size += n->size;
        b->next = n->next;
        if (n->next) n->next->prev = b;
    }
    /* Coalesce backward. */
    if (b->prev && b->prev->free) {
        block_header_t *p2 = b->prev;
        p2->size += b->size;
        p2->next = b->next;
        if (b->next) b->next->prev = p2;
    }
}
```

Once `kmalloc` works, the rest of the kernel gets dramatically easier; drivers and the window manager simply allocate what they need.

## The stack of abstractions

```text
kmalloc / kfree              (arbitrary sizes)
   |
   |--- vmm_map              (virtual -> physical, 4 KiB pages)
           |
           |--- pmm_alloc_frame   (free physical frames)
                   |
                   |--- E820 map  (what RAM exists)
```

Each layer only knows about the one below it. That separation is what keeps a memory manager understandable, and it is a pattern you will reuse everywhere in the kernel.

You now have a kernel that can hand out RAM in any shape it likes. The next chapter uses that to run more than one thing at a time.

## Exercises

1. **Watch free memory drop.** After `pmm_init`, print `pmm_total_frames() * 4 / 1024` and `(pmm_total_frames() - pmm_used_frames()) * 4 / 1024` (total and free, in MiB). Then `kmalloc(1024 * 1024)` ten times, never freeing, and print the values again. You should see free memory drop by ~10 MiB. Free everything, print again; it should bounce back.

   *Hint:* The heap demand-grows in 16-page (64 KiB) chunks at a time, so the first few mallocs may not move the PMM at all. Make the loop allocate at least a megabyte each time to see steady progress.

2. **Stress-test coalescing.** Allocate 1000 blocks of 100 bytes each, store their pointers in an array, free every other one. Then try to allocate one block of 50000 bytes. It should succeed *only if* coalescing is working; without coalescing the heap would be a checkerboard of busy and free 100-byte holes. Compare to a version of `kfree` with both `if (b->next && b->next->free)` and `if (b->prev && b->prev->free)` commented out.

   *Hint:* This is the canonical fragmentation test. A useful invariant: after freeing everything, the heap should consist of a single free block as large as the total mapped size.

3. **Map a high address by hand.** Pick virtual address `0xFFFFFF8000000000` (the top of canonical 48-bit address space). Allocate one frame with `pmm_alloc_frame()`. `vmm_map` the two together. Write a value to `*(uint64_t*)0xFFFFFF8000000000`, read it back, confirm it round-trips. Then `vmm_unmap` and try to read again; you should get a page-fault panic (using your Chapter 6 handler).

   *Hint:* x86-64 requires that the upper bits of a canonical address be a sign-extension of bit 47, so `0xFFFFFF80...` is canonical but `0x000000F0...000000` near 2^47 may not be. Stick to the low half or the high half and you will be fine.

4. **Implement a second-fit allocator and compare fragmentation.** Replace the first-fit loop in `kmalloc` with **best-fit** (scan all blocks, pick the smallest that fits) and a separate variant with **next-fit** (start from where the last allocation ended). Run the exercise-2 stress test against each. First-fit is fastest; best-fit fragments the least but is slowest; next-fit is a fast compromise. There is no single right answer; that is the whole point.

   *Hint:* Add a `static block_header_t *cursor` for next-fit, save where you left off after each allocation, and start the loop from there. For best-fit, walk the whole list, remembering the smallest fitting block, and only allocate at the end. Measure with a counter incremented each time you split a block, and a counter for the maximum free-block size at the end.

With memory under control, we can finally make the kernel do *several things at once*.
